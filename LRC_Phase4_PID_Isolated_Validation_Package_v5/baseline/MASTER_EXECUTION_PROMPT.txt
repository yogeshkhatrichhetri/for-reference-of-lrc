4. GOVERNING PHYSICS: DERIVE BEFORE BUILDING
====================================================================

4.1. Kirchhoff's Voltage Law

The physical circuit is governed by:

    e_i(t) - R*i(t) - R_eq*i(t) - L*di(t)/dt - e_o(t) = 0

Equivalently:

    L*di(t)/dt = e_i(t) - R_total*i(t) - e_o(t)

For the original series circuit, where the same current flows through
the resistor, inductor, and capacitor:

    i_C(t) = i(t)

    C*de_o(t)/dt = i(t)

Therefore:

    di(t)/dt = [e_i(t) - R_total*i(t) - e_o(t)] / L

    de_o(t)/dt = i(t)/C

These equations must be implemented correctly in the first-principles
Simulink plant.

4.2. Canonical transfer function

With zero initial conditions:

    G(s) = E_o(s) / E_i(s)

         = 1 / [L*C*s^2 + R_total*C*s + 1]

Equivalently:

    G(s) = (1/L/C) /
           [s^2 + (R_total/L)*s + 1/(L*C)]

Using the supplied parameters:

    R_total = 50 ohms

    L*C = 0.00051

    R_total*C = 0.0255

Therefore:

    G(s) = 1 / (0.00051*s^2 + 0.0255*s + 1)

         = 1960.784314 /
           (s^2 + 50*s + 1960.784314)

Implement this canonical model using a native Simulink Transfer Fcn
block.

Do not use this Transfer Fcn block as a substitute for the separate
first-principles implementation.

5. ANALYTICAL BASELINE: INDEPENDENTLY VERIFY THE NUMBERS
====================================================================

Before controller tuning, calculate the theoretical open-loop
characteristics.

Natural frequency:

    omega_n = sqrt(1/(L*C))

Expected value:

    omega_n approximately 44.28 rad/s

Damping ratio:

    zeta = R_total/2 * sqrt(C/L)

Expected value:

    zeta approximately 0.5646

Damped natural frequency:

    omega_d = omega_n*sqrt(1 - zeta^2)

Expected value:

    omega_d approximately 36.55 rad/s

Underdamped open-loop poles:

    s = -zeta*omega_n +/- j*omega_d

Expected approximately:

    s = -25 +/- j*36.55

Peak time for the standard second-order step response:

    t_p = pi/omega_d

Expected value:

    t_p approximately 0.086 s

Percentage overshoot:

    Mp_percent = 100*exp(-zeta*pi/sqrt(1-zeta^2))

Expected value:

    Mp_percent approximately 11.7%

DC gain:

    G(0) = 1

These are analytical checks, not fabricated simulation measurements.

Calculate them independently and print the numerical results in the
MATLAB Command Window.

Check the calculated poles against the transfer-function denominator.

If the calculated results differ materially from the expected
values, stop and investigate the discrepancy before implementing
the controller.

Do not proceed with controller tuning while the baseline plant
contains an unresolved mathematical inconsistency.

8. LOAD-DISTURBANCE MODELING
====================================================================

A disturbance must have an explicitly defined physical injection
point and mathematically consistent implementation.

Do not refer to an arbitrary additive voltage step as a load
disturbance.

Use a configurable load-current disturbance at the capacitor
output node.

If the disturbance is modeled as a load current drawn from the
capacitor node, modify the capacitor equation to:

    C*de_o/dt = i_series - i_load

Therefore:

    de_o/dt = (i_series - i_load)/C

The inductor/resistor branch continues to satisfy:

    L*di_series/dt = e_i - R_total*i_series - e_o

When:

    i_load = 0

the system must reduce to the original CTMS series LRC model.

When:

    i_load > 0

the load draws current from the output node and perturbs the
capacitor voltage.

The disturbance must be injected at the capacitor-node current
balance, not at an arbitrary location in the inductor equation.

Implement the disturbance using native Simulink blocks, such as
Step, Sum, and Gain, with a configurable amplitude and application
time.

    Scenario 1: No disturbance; establish controller tracking

    Scenario 2: Apply a load-current disturbance; evaluate
               disturbance rejection and recovery.

10. PID GAIN DESIGN: ANALYTICAL DERIVATION REQUIRED
====================================================================

Do not select Kp, Ki, Kd, or N arbitrarily.

Derive and explain the controller parameters before finalizing
the Simulink implementation.

Use pole placement, desired characteristic-polynomial matching,
or another mathematically justified method.

10.1. Start with the canonical plant

    G(s) = 1/D(s)

where:

    D(s) = L*C*s^2 + R_total*C*s + 1

10.2. Establish the ideal parallel PID relationship

For an ideal, unfiltered parallel PID:

    C_PID(s) = Kp + Ki/s + Kd*s

Under unity negative feedback, the closed-loop characteristic
polynomial is:

    L*C*s^3
    + (R_total*C + Kd)*s^2
    + (1 + Kp)*s
    + Ki
    = 0

Use this relationship to establish a transparent analytical
starting point for pole placement.

If the desired monic cubic polynomial is:

    s^3 + a2*s^2 + a1*s + a0

then the corresponding ideal-PID coefficient relationships are:

    Kd = L*C*a2 - R_total*C

    Kp = L*C*a1 - 1

    Ki = L*C*a0

Check dimensional consistency and ensure that the resulting
characteristic polynomial has the intended coefficients.

These formulas apply to the ideal, unfiltered parallel PID model.
Do not blindly apply them to a filtered derivative implementation
and claim exact pole matching.

10.3. Account for derivative filtering

The practical derivative path is:

    D(s) = Kd*N*s/(s + N)

When derivative filtering is used, account for the additional
dynamics introduced by the filter.

For this filtered controller, the unity-feedback characteristic
equation can be written as:

    s*(s + N)*D(s)
    + Kp*s*(s + N)
    + Ki*(s + N)
    + Kd*N*s^2
    = 0

Expand this expression and show how N, Kp, Ki, and Kd influence
the resulting closed-loop polynomial.

Use the appropriate filtered model for final verification.

Do not report exact pole placement when the implemented filtered
controller has not actually been matched to the stated polynomial.

10.4. Choose desired closed-loop behavior

The design must prioritize:

    - Stable closed-loop dynamics
    - Peak overshoot below 2%
    - Settling time below 0.05 s
    - Negligible steady-state error under the stated conditions
    - Acceptable control effort
    - No persistent integrator windup
    - Recovery from the specified load disturbance

Select appropriate desired poles or performance specifications
before calculating the final gains.

Report the desired pole locations, the resulting controller gains,
and the reasoning behind the derivative-filter coefficient.

Consider the actuator saturation during tuning.

If the analytically designed gains produce excessive control
effort or fail under saturation, refine the design while preserving
a documented mathematical basis.

If exact analytical matching conflicts with the filter, saturation,
or discrete sampling constraints, make that limitation explicit.

Do not invent gain values and then construct a derivation intended
to justify them retrospectively.

10.5. Required gain report

Document:

    Kp
    Ki

    N

    Desired closed-loop poles
    Calculated characteristic polynomial
    Assumptions and approximations

13. QUANTITATIVE ACCEPTANCE CRITERIA
====================================================================

Define and evaluate explicit acceptance tests.

Do not mark a criterion as passed without supporting numerical
evidence.

TEST 1: PHYSICAL MODEL CORRECTNESS

Confirm that:

    di/dt = (e_i - R_total*i - e_o)/L

    de_o/dt = i/C

for the original series circuit.

For the load-disturbance variant, confirm that:

    de_o/dt = (i_series - i_load)/C

TEST 2: ANALYTICAL BASELINE

Confirm that the plant parameters reproduce the expected natural
frequency, damping ratio, poles, peak time, and open-loop overshoot
within an explicitly defined tolerance.

TEST 3: PLANT EQUIVALENCE

Compare the first-principles and Transfer Fcn outputs.

Report:

    Maximum absolute error
    Maximum relative error where meaningful
    Final-value difference
    Verification tolerance
    Pass/fail result

TEST 4: CLOSED-LOOP STABILITY

Establish that the implemented closed-loop model is stable under
the tested operating conditions.

For the analytical linear model, investigate the closed-loop poles
or characteristic polynomial.

For the implemented nonlinear or saturated model, support the
assessment with appropriate simulation results.

Do not infer stability from one apparently well-behaved short trace.

TEST 5: OVERSHOOT

Target:

    PID peak overshoot < 2%

Use the final steady-state value and define the overshoot
calculation explicitly.

For the positive 1.53 V reference, evaluate:

    Mp_percent = 100*(y_peak - y_final)/y_final

when that formula applies to the measured response.

Distinguish a tracking step response from a disturbance-response
transient.

TEST 6: SETTLING TIME

Target:

    PID settling time < 0.05 s

Use a 2% settling band around the final reference value.

For a 1.53 V final reference, the band is:

    1.53 +/- 0.0306 V

Define settling time as the first time the output enters the band
and remains within it for the remainder of the relevant baseline
response.

Do not use the duration of a Scope window as a substitute for
measuring settling time.

TEST 7: RISE TIME

Report the 10%-to-90% rise time for the reference step.

Do not invent an additional rise-time acceptance threshold if
none has been specified.

TEST 8: STEADY-STATE ERROR

Report:

    e_ss = e_ref - e_o,final

Evaluate the steady-state error separately for P, PI, and PID.

Explain the effect of integral action.

TEST 9: CONTROL EFFORT

Report the maximum and minimum controller output, whether
saturation was reached, and the time spent saturated.

Verify anti-windup recovery when applicable.

TEST 10: DISTURBANCE REJECTION

Report:

    Peak deviation from the reference
    Maximum absolute tracking error
    Recovery time
    Residual steady-state error

Define the recovery criterion and tolerance.

TEST 11: CONTROLLER IMPLEMENTATION EQUIVALENCE

Compare the explicit PID with the native PID Controller block
under matched configurations.

Report output differences and control-effort differences.

Test continuous and discrete configurations separately.

TEST 12: REPRODUCIBILITY

Confirm that the model can be reopened and run from a clean
MATLAB session using the delivered initialization script.

A test that has not actually been executed must be marked
UNVERIFIED, not PASS.
